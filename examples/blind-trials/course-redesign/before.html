UI 自動化測試｜使用 Playwright × AI 打造高品質測試工作流

從業務流程、測試案例到 Playwright 自動化與 AI 協作

從釐清業務流程與界定測試範圍與案例，透過 Playwright 與 AI Agent 建立可執行、可診斷、可維護的 UI 自動化測試工作流。不只教你寫腳本，更涵蓋測試案例設計、Evidence 診斷、POM 與團隊測試流程。

課程以「Pet Shop 寵物購物系統」的購物主流程作為貫穿案例，從業務流程、測試案例、Playwright 自動化一路延伸到失敗診斷與可維護測試架構，建立一套能實際應用於開發與測試工作的 UI 自動化測試流程。

課程大綱

單元內容重點
一、UI 自動化定位與測試策略UI 自動化測試的角色與適用範圍；Unit、Integration 與 E2E 的測試分層；Smoke Test 與 Regression Test 驗證策略
二、Playwright 環境建置Node.js、Python 與開發環境設置；安裝 Playwright 與瀏覽器
三、測試案例設計測試案例的基本結構；BDD 與 Given / When / Then；測試案例的顆粒度與責任範圍
四、Playwright 基礎操作與實務應用CLI、Skill 與 Test 的基本分工；觀察、操作與驗證 Web UI；建立並執行第一個測試腳本；使用 AI Agent 與 HTML Report 檢視結果
五、Playwright 定位與腳本能力UI、DOM 與 Accessibility 基本概念；Locator 與穩定定位策略；User Actions 與 Assertion
六、AI Agent 協作以 AI Agent 生成測試腳本；審查與修正 AI 產出
七、失敗診斷Screenshot、Trace Viewer、HTML Report；整理 Evidence 並引導 Agent 修正；重新執行與確認修正結果
八、Page Object Model 與可維護測試架構POM 的導入時機；Helper Function 與 POM 的差異；Page Object 的設計與責任邊界；Locator、頁面操作與測試意圖分離；Fixture 與 POM 整合
九、測試資料與環境測試資料的 Seed、Reset 與 Cleanup；測試資料隔離與團隊協作

常見問題與備註

Q：這門課會教 Playwright 的基本操作嗎？
會，並會從基本腳本一路串到測試案例設計、AI Agent 協作、失敗診斷與 POM 測試架構。
Q：課程會使用哪些工具？
主要使用 Playwright Test、CLI 與相關 Skill / MCP，並搭配 VS Code 與 Codex 或 Claude 等 AI Agent 開發工具；但不限定使用特定單一 AI Coding 工具。
Q：需要從零開發 Pet Shop 系統嗎？
不需要。Pet Shop 是課程提供的範例系統，主要用來作為 UI 自動化測試與流程驗證的練習對象。
Q：需要具備 Playwright 經驗嗎？
不需要熟悉 Playwright，但建議具備基本程式與網頁概念。
Q：會提供課程錄影嗎？
會提供完整課程錄影，方便課後複習與反覆練習。
